## 1. 시작하기

Node.js 24 이상이 필요하다. 외부 npm 패키지가 없어 `npm install` 없이 실행할 수 있다.

```sh
node --version
npm test
npm run dev
```

표시되는 `http://127.0.0.1:3000`을 연다. 개발 서버는 로컬 컴퓨터에서만 접근하도록 제한한다. 포트가 사용 중이면 `.env`의 `PORT`를 바꾼다. 종료는 Ctrl+C다.

- `public/`의 HTML·JS·CSS는 브라우저 새로고침으로 반영된다.
- `lib/`·`worker/` 서버 모듈 변경은 Ctrl+C 후 `npm run dev`로 재시작한다.
- `npm run build`로 `dist/server/index.js`와 `worker/index.js`를 생성한다. 생성 파일을 직접 편집하지 않는다.

## 5. 로컬 관리자·저장소

`.env.example`을 `.env`로 복사한다. `ADMIN_TOKEN`에 24자 이상의 별도 비밀값을 직접 설정하고 서버를 재시작한다. `?page=admin` 화면에서 그 값으로 로그인한다. 키는 채팅에 붙이지 않는다. 로컬에서는 운영 Sites 계정 로그인을 사용할 수 없으며 토큰 방식만 사용한다.

`.local-data/`가 로컬 R2 대체 저장소다. 관리자 수정·업로드·암호화 연결값을 이 폴더에 보관한다. 조건부 쓰기와 임시 파일→원자적 이름 변경으로 저장 충돌과 부분 쓰기를 방지한다. 이 폴더는 Git·ZIP에 넣지 않는다. 운영 자료를 가져온 저장소가 아니므로 초기 데이터와 새 로컬 변경만 존재한다. 개발 서버는 웹 요청의 Sites 사용자 인증 헤더를 제거한다.

관리자 인증값을 바꾸면 기존 로컬 세션과 OC 암호화 키도 달라진다. 기존 연결값을 읽지 못하면 관리자 화면에서 다시 등록한다. 로컬과 운영은 서로 다른 인증값을 사용한다.

## 6. 운영 배포와 필수 설정

운영은 Cloudflare Worker 기반 Sites 웹앱이다. `.openai/hosting.json`의 Site ID와 R2 바인딩 `BUCKET`은 식별·연결 설정이고 비밀키가 아니다. 현재 Site를 수정할 때는 ID를 유지한다. 별도의 새 사이트를 만들 때는 새 사이트에 맞는 ID·저장소·비밀값을 설정해야 한다.

| 설정 | 용도 / 이전 여부 |
| --- | --- |
| BUCKET | 운영 R2 바인딩. 운영 실제 데이터는 이 ZIP에 없음 |
| ADMIN_EMAIL / ADMIN_USER_ID | Sites가 검증한 사용자 헤더와 비교하는 운영자 허용 목록. 로컬에서는 사용하지 않음 |
| ADMIN_TOKEN | 관리자 토큰 로그인·세션 서명·OC 암호화. 패키지에 값 없음 |
| LAW_API_OC | 선택 서버 환경값 또는 관리자 화면에서 등록한 승인 OC. 값 미포함 |
| LAW_UPDATE_SIGNING_KEY | 갱신 경로 전용 32바이트 키의 64자리 hex. 값 미포함 |
| HOLIDAY_API_KEY | 선택. 공공데이터포털 한국천문연구원 특일 정보 일반 인증키(Decoding). 있으면 공휴일 정기 갱신을 건너뜀. 값 미포함 |

다른 호스팅에서는 Sites 인증 헤더의 신뢰 근거가 사라진다. 해당 헤더를 외부에서 임의 전달하게 두지 말고, 검증된 인증 게이트웨이를 구현하거나 관리자 토큰 방식만 사용해야 한다. R2 바인딩도 해당 호스팅에 맞춰 설정한다.

평일 월~금 09:00 Asia/Seoul 법령 갱신은 Worker 자체 cron이 아니라 운영 사이트와 연결된 외부 클라우드 예약 작업이다. 저장소 복사·GitHub push만으로 예약 작업이나 R2·환경 변수는 이전되지 않는다. 공휴일 제외는 서버에 `HOLIDAY_API_KEY`가 있을 때 서버가 판단한다(예약 작업 쪽 변경 불필요). 서명 프로토콜은 `worker/scheduler-auth.mjs`, `/api/updates/instructions`, README를 참고한다. 새 배포에서 예약 작업은 별도로 연결해야 한다.

GitHub 저장소는 소스 인수인계용이며 push만으로 운영 사이트를 자동 배포하는 CI/CD는 설정되어 있지 않다. Sites 배포는 현재 사용 중인 소스 push→빌드 아카이브→버전 저장→배포 절차를 사용한다. 사용자 키나 토큰을 GitHub에 커밋하지 않는다.

## 7. 공식 API·자료 이용과 알려진 제약

- 주요 법령 8개는 확보한 조문·부칙을 제공한다. 별표·서식 파일을 모두 확보한 것은 아니다.
- 국세법령정보시스템 판례는 법제처 `target=prec`, `datSrcNm=국세법령정보시스템` 목록만 사용한다(본문 HTML은 국세청 사이트로 연결되는 안내 화면뿐). 목록의 `법원명`은 비어 있어 사건번호에서 법원을 분리한다. 대법원 출처 판례(`datSrcNm=대법원`)는 사건명으로 국세·지방세를 분류하고, 하도급은 본문 검색(`search=2`)으로 찾아 JSON 본문을 수록한다. 운영 서버에서의 실제 수집 성공은 OC 등록 후 확인해야 한다.
- 국세청 실무 자료와 추가 판례 링크의 본문·첨부·국세청 편집 요지는 미확보다. 이를 읽은 것처럼 요약하거나 AI 근거로 쓰지 않는다.
- 과거 법령이 없으면 확인 불가다. 현행으로 대체하지 않는다. 같은 사건의 심급·후속 판단을 합쳐 단정하지 않는다.
- 기존 R2의 새 시드 추가·삭제 보존·링크 보정 로직을 확인한다. `seed.json`을 바꿨다고 기존 관리자 수정 문서가 모두 덮어써지는 구조가 아니다.
- 자료별 재게시·다운로드 조건과 출처를 유지한다. 공개 페이지라는 이유만으로 자동 수집·재배포가 허용된다고 가정하지 않는다.

## 8. 검증과 비용

자동 검증은 테스트 파일 13개, 전체 77개 테스트다(2026-10-21: 판례 수집 범위·사건번호 분리·일괄 공개·본문 보강·수집 파일 검증·법령 본문 변환·지방세 공개·공휴일 건너뜀 추가). 검색·시점·권한·OC 암호화·수집 실패/복구·링크 자료의 근거 제외·소스 URL 보정 등을 검증한다. UI는 이전 작업에서 320~850px 모바일·태블릿과 1440px PC를 격리 브라우저로 확인했다. 실제 휴대전화 터치 테스트를 수행했다고 간주하지 않는다. 이후 변경은 다시 검증한다.

로컬 개발 서버에는 유료 서비스 호출이 기본 활성화되어 있지 않다. 공식 API를 직접 사용할 때는 승인 OC와 제공기관 조건·호출 한도를 확인한다. 호스팅·R2 저장량·요청·전송·GitHub 비공개 저장소 및 Actions·Claude 사용료에는 각 서비스의 이용 한계와 비용이 적용될 수 있다. 별도 가입·결제·자동 배포·유료 AI 연결을 추가하지 않았다.

## 9. ZIP 포함·제외

포함: 편집 가능한 앱 소스, 검토된 초기 공식 자료, 테스트, 빌드·로컬 실행 도구, `.env.example`, 설명서, 기존 Sites 식별 설정.
제외: `.git` 이력·원격 인증 정보, 실제 `.env`·키·OC·토큰, 운영 R2 데이터, 개인 보관함, 로컬 저장소·로그·임시 작업물. `worker/index.js`는 생성물이며 소스 수정 후 다시 빌드한다.
